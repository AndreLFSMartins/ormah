O problema

O _ingest_session só pula um arquivo quando o hash do arquivo inteiro é idêntico. Numa conversa ativa, cada turn novo muda o hash, então o watcher re-parseia o .jsonl todo e re-extrai memórias de todos os turns de novo — gerando um novo lote de nós a cada modificação. Numa store real isso virou ~69% dos nós (≈6,3k de 9,1k), com conversas de 22 turns produzindo 229 nós.

Causa raiz O parser já suporta leitura incremental — parse_transcript(path, start_offset=…) devolve TranscriptResult.end_offset. O watcher nunca usou. É feature meio-implementada desde o commit de import (março/2026), não regressão de PR recente.

A estratégia

Fiar o end_offset persistido dentro do _ingest_session: reabrir o arquivo a partir do offset guardado, ingerir só a fatia nova, avançar o cursor. O gate min_turns passa a valer para a fatia nova (appends pequenos esperam acumular sinal). Se o arquivo encolher (compactação/reescrita), o cursor reseta para 0 e re-ingere o todo.

Escopo: um arquivo de código — src/ormah/background/session_watcher.py — mais seu arquivo de teste. O parser.py fica intacto.

A implementação (núcleo)

Trecho de _ingest_session — do hash check ao _save_state 
existing = state.get(rel)
if existing and existing.get("hash") == h:
    return False

# Incremental: only parse the turns appended since the last ingest.
prev_offset = existing.get("end_offset", 0) if existing else 0
try:
    size = path.stat().st_size
except OSError as e:
    logger.warning("Cannot stat %s: %s", path, e)
    return False
if prev_offset > size:
    prev_offset = 0  # file shrank (compaction/rewrite) → re-ingest whole

result = parse_transcript(path, start_offset=prev_offset)

if result.user_turn_count < min_turns:
    return False  # too few NEW turns; offset unchanged → reconsidered later

# … ingest_conversation(content=result.conversation, …) …

prev_turns = existing.get("user_turns", 0) if (existing and prev_offset > 0) else 0
state[rel] = {
    "hash": h, "end_offset": result.end_offset,
    "last_ingested": datetime.now(timezone.utc).isoformat(),
    "session_id": result.session_id, "space": space,
    "user_turns": prev_turns + result.user_turn_count,
    "node_ids": prev_node_ids + new_node_ids,
}

Limitação conhecida

Documentar, não corrigir aqui Uma reescrita in-place do prefixo que não encolhe o arquivo (raro; /compact encolhe) não é detectada pelo reset por tamanho e ingeriria a partir do offset velho. Rastreável à parte se aparecer. Reset robusto por hash-de-prefixo fica fora de escopo.
