Reversible Promotion + Seven-Day Initial Lease

Give archival nodes a way back to working on confirmed use, and extend new nodes from a ~29-hour default lease to seven days.

Overview

This plan implements two complementary lifecycle improvements to Ormah's memory system:

  • Reversible promotion: Confirmed re-use of an archived node brings it back to working tier, unless the node was explicitly superseded by a consolidation.
  • Extended initial lease: New nodes now start with a 5.814-day stability (seven days at retrieval threshold 0.3) instead of 1.0 days (~29 hours).

The architecture is minimal: one pure function (lifecycle.promotion_floor) supplies the floor; the tier flip happens inside MemoryEngine._record_confirmed_use, which already owns the at-most-once confirmed-use claim. A new superseded_by field, written by the consolidator, blocks automatic promotion for exactly the nodes a consolidation replaced.

Note: builder.py is not in the spec's original file list but is required. _index_file_nodes_only runs INSERT OR REPLACE INTO nodes with an explicit column list. In SQLite, REPLACE is DELETE+INSERT, so any omitted column reverts to its DEFAULT. Without this change, the consolidator's own update_node(tier=archival) re-indexes the file and wipes superseded_by back to NULL. The promotion gate itself reads Markdown and blocks correctly, but the index column would be permanently NULL, which violates the contract #209 relies on.

1 Seven-Day Lease & Promotion Floor

Task 1: Seven-day lease default + promotion_floor

Files: src/ormah/config.py, src/ormah/lifecycle.py · Tests: tests/test_lifecycle.py, tests/test_background/test_decay_manager.py

Purpose

Set the initial stability to 5.814 (days), which gives new nodes a seven-day unused lease instead of ~29 hours. Provide a pure function promotion_floor(stability, initial_stability) that lifts a node's stability to at least the initial value, used by promotion logic.

Interfaces

Consumes
lifecycle.retrievability(days_since, stability, *, fallback_stability=1.0) — already exists
Produces
lifecycle.promotion_floor(stability: float, initial_stability: float) → float, used by Task 5
Settings.fsrs_initial_stability == 5.814, used by Tasks 4 and 5

Design Note: max, Never a Sum

The floor uses max rather than addition because it makes "the post-update floor does not amplify the same event into a longer-than-initial lease" structural rather than incidental, and repeated promotions are idempotent.

Steps

  1. Write failing lease + floor tests
  2. Run tests to verify they fail
  3. Change fsrs_initial_stability default in config.py to 5.814
  4. Add the pure promotion_floor function to lifecycle.py
  5. Run tests to verify they pass
  6. Write the decay-cadence test (sets stability directly, not via remember())
  7. Check config suite did not regress
  8. Lint and commit

3 Index Column & Migration

Task 3: superseded_by in schema, migration and reindex

Files: src/ormah/index/schema.sql, src/ormah/index/db.py, src/ormah/index/builder.py · Tests: tests/test_index/test_migration_superseded.py (create), tests/test_index/test_builder.py

Purpose

Add the superseded_by TEXT column to SQLite schema and migrations, and update reindex to preserve it during INSERT OR REPLACE operations.

Design Note: The Builder Change is Load-Bearing

_index_file_nodes_only runs INSERT OR REPLACE INTO nodes with an explicit column list. In SQLite, REPLACE is DELETE+INSERT, so a missing column reverts to DEFAULT (NULL). Task 6's consolidator marks the node, then calls update_node(tier=archival), which calls builder.index_single; without this change the marker is wiped within the same loop iteration.

Steps

  1. Write failing migration test (adds column, leaves existing rows NULL, is idempotent)
  2. Write failing reindex-survival test
  3. Add column to fresh-store schema
  4. Add migration entry to enrichment_migrations
  5. Update _index_file_nodes_only to include superseded_by (19 columns, 19 values, count carefully)
  6. Run tests to verify they pass
  7. Lint and commit

5 Promotion Inside Confirmed Use

Task 5: Promotion inside _record_confirmed_use

Files: src/ormah/engine/memory_engine.py · Tests: tests/test_engine/test_reversible_promotion.py (create), plus 5 existing test files

Purpose

Move archival nodes back to working when they receive a qualified confirmed-use signal, unless marked superseded. Apply the promotion floor so post-update stability reaches at least the initial value.

_claim_confirmed_use already fail-closes on correct signal, source, and was_injected. All callers pass through it. Placement inside _record_confirmed_use inherits qualification for free. A contract test prevents future callers from reopening the hole.

6 Consolidation Provenance

Task 6: Consolidation provenance and its ordering fail-safe

Files: src/ormah/engine/memory_engine.py (new method), src/ormah/background/consolidator.py · Tests: tests/test_background/test_consolidator.py

Purpose

Mark consolidated source nodes with the ID of the consolidation node that replaced them. Enforce marking before demotion — the fail-safe: a crash between the two leaves the node marked and working (harmless), not unmarked and archival (promotable).

Design Notes

Why separate writer: superseded_by is absent from UpdateNodeRequest, so needs its own writer decorated @_serialized_memory_operation.

Why no touch_updated(): The next line is update_node(tier=archival), which already advances updated. A second bump would be redundant.

Steps

  1. Write failing provenance tests (marks sources, survives reindex, blocks promotion, fail-safe on crash)
  2. Add _mark_superseded method to MemoryEngine
  3. In consolidator.py's _apply_consolidation, call _mark_superseded before update_node
  4. Run consolidator, background, and engine tests
  5. Lint and commit
