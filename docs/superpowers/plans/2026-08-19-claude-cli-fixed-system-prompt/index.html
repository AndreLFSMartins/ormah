Why This Plan Is Superseded

This plan was written against a design that has been withdrawn. Two independent reasons, both established by measurement rather than review:

  1. Premise does not reproduce. Targeted 3.0× saving from --system-prompt alone (7,726 → 110 cache_write). Re-measured on claude-haiku-4-5: --system-prompt alone is 1.19×. The saving lives in --setting-sources "", and the two flags together are 2.19×.
  2. Quality gate approves without measuring. An independent audit of all 26 code blocks found: shell word-splitting assumptions, AFTER comparing file with itself and passing, injection detection matching titles only, 8% judgment flip rate, and combine({}) returning PASS.

Do not reuse Task 2 tests — three of five assert the prompt contains the substring the prompt contains.

Still valid if revived: distance→similarity conversion (1 - d²/2), vector query shape, pair-shape keys, every CLI entry point, and combine()'s failure-over-invalidity precedence.

Plan Overview

Goal and Architecture

Pin a constant --system-prompt on every claude -p call (3.0× cheaper per call via a stable cache prefix) and log per-call usage/cost from the CLI envelope.

Architecture: Two surgical edits inside ClaudeCliAdapter.generate() — one argv flag fed by a module constant, one best-effort log line after envelope parse. Because the adapter is shared by seven callers, quality is gated on seven axes: six A/B agreement arms (linker, duplicate-merger, conflict-detector; each in single and batched paths) plus one ingest extraction smoke.

Every before leg runs on current code. Tasks 1 and 1b must precede any edit.

Task 1: Baseline Legs — BEFORE any code change

14 steps | ~100 calls | 15–20 min

Produces: pairs.jsonl (mined corpus); before.json, before2.json (two independent verdicts on unchanged code, single path); before-batch.json, before2-batch.json (same two, batched path at K=10); ingest-before.json (extraction smoke).

Prompt-Text Constraint (Council Round 2, C2)

The prompt must not defer to instructions in the user message — the trust boundary note says transcript is UNTRUSTED. Every real caller puts load-bearing rules after the material (ingest appends "Now extract…" after </conversation>; pair judges append rules after Memory A/B blocks). Saying the material "follows the task" demotes those rules to data. Instead, name the untrusted REGIONS: <conversation> tags and Memory A/B blocks. Keep everything outside binding.

5 steps | Modify 1 file + tests | Best-effort observability

Implementation Notes

For subagents executing individual tasks

Each task file is self-contained and names its exact prerequisites and outputs. Read the overview first — especially Global Constraints — before starting your task.

Measurement integrity: All BEFORE legs must run on unchanged code. The two BEFORE replicates define the noise floor; AFTER is compared against both and judged on the worse. This prevents a lucky pairing from carrying the arm.

Sequential, never parallel: All baseline and AFTER legs run sequentially under identical machine conditions. Parallel runs add noise that makes the floor meaningless.

Stop rules are hard: An A/B arm below the noise floor (agree_rate < 0.90), or a destructive caller with too few source labels for its cap, means the judge cannot measure — not that you should re-tune the threshold. Report to André; the fix is a different measurement design, not a code edit.
