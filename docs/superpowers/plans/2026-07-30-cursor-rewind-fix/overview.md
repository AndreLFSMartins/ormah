# Cursor Rewind Loop Fix (#154) — Implementation Plan (Overview)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax. Each subagent gets ONLY its task file + this overview.

**Goal:** Stop the session-watcher cursor from ever moving backward, killing the permanent re-extraction loop that re-ingested one transcript 5,342× (~98% of all LLM ingest cost).

**Architecture:** Two independent layers. (1) A progress gate on the *capped drain* inside the orphan-recovery path of `_ingest_session` — recovery is only allowed when the drain slice itself surpasses the original cursor; otherwise the tail is **explicitly abandoned**: the cursor advances past it, the byte range is recorded durably in `skipped_slices` (reason `orphan_above_cap`), and the job completes — zero LLM calls, no reliance on the frozen-prefix side effect in `_run_job` (council R1: a bare `NO_PROGRESS` would be converted into an EOF bump + dead-letter by `_idle_with_unsafe_tail`/`_mark_frozen_prefix_consumed`, with no loss record). This kills both the loop and its cost at the source. (2) A monotonic invariant inside `_commit_state` as a structural backstop: `end_offset` may never decrease unless the caller passes `allow_rewind=True` (file-shrunk re-ingest; future backfill). The compare-and-clamp runs INSIDE the `state_lock` critical section (council R1), and clamps ONLY the `end_offset` field, never the whole entry, so failure counters / quarantine trails still persist.

**Tech Stack:** Python 3.11+, pytest (`asyncio_mode=auto`), ruff (line-length 100). No new dependencies.

**Evidence base:** `docs/investigation-2026-07-30-consolidacao-ingestao.md` (+ `docs/investigation-2026-07-30-cursor-rewind-loop.md`). Live repro: `scratchpad/repro_rewind_loop.py` (period-7 cyclic cursor, 8,034-byte retreat).
