Embedding delta backfill

2026-06-16 · 10 tasks · branch fix/embedding-delta-backfill

Recover only the missing vectors, off the bind path — bounded even under a poison node, and independent of the scheduler.

Goal & architecture

Goal: bound startup embedding cost to O(gap) and make it non-blocking — recover only missing vectors (delta) via a recurring background job, never a synchronous full re-embed before the port binds. Recovery must stay bounded under permanent per-node failures and must not depend on the scheduler being healthy.

Architecture: move recovery out of startup() into an embedding_backfill job with two modes — delta (anti-join → only nodes missing from node_vectors_rowids) and schema bump (re-embed all, version advanced only when verified complete). Persistently-failing nodes are quarantined (bounded retry budget). Completeness is checked against vec_count, catching silent sqlite-vec drops. A scheduler-independent post-bind one-shot guarantees recovery even if start_scheduler fails.

Council R1 fixes baked in

C1 — poison loop closedquarantine + retry budget bound a schema migration to O(N × budget) one-time, then delta forever — never an unbounded full re-embed.
I1 — scheduler dependency closeda daemon-thread one-shot in lifespan runs reconciliation even if start_scheduler raised; the scheduler still drives the recurring cadence on the happy path.
  • I2 / I4: version advances only on verified completeness (vec_count); incomplete runs surface as non-ok job health.
  • I3: embedding_gap + embedding_schema_version in stats() + an E2E recovery test.
  • m1 / m2: empty-text nodes excluded from delta; "startup doesn't embed" wording corrected (warmup still runs).
  • Scale: anti-join via LEFT JOIN ... WHERE v.id IS NULL.
