The O(n²) problem

run_auto_linker (src/ormah/background/auto_linker.py) scans every node each run and, per node, re-encodes its text, runs a brute-force vec_store.search (itself O(n)), and calls the LLM per surviving candidate. Total cost is O(n²) compute plus O(candidates) LLM calls, repeated every auto_link_interval_minutes (default 1440 = 24h).

_find_link_candidates — the maintenance-protocol preview reached via get_maintenance_batches → maintenance_manager — has the same shape, and additionally sorts with ORDER BY RANDOM(). Both sites are fixed with one technique.

The skip happens too late

auto_link_checked already skips already-evaluated pairs — but only after the expensive encode + search. So the scan cost stays unbounded in n regardless. On the real store (8,355 nodes) most of each run is spent re-encoding and re-searching nodes that yield nothing: 4,776 nodes (57%) have never produced an evaluated pair.

Approach A — watermark in meta

One mechanism serves both backfill and incremental — they differ only in the watermark's initial value.

Backfill drains the historical backlog; incremental picks up only new or changed nodes. An absent watermark behaves as epoch, so a fresh deployment naturally backfills from the oldest node and then settles into cheap incremental runs. Correctness rests on this single invariant.

No structural cost

No new table, no new dependency, no change to the nodes schema. The watermark rides on infrastructure that already exists.

The incremental cycle

Each run reads the watermark, pulls one bounded, ordered window above it, processes node by node, and advances the watermark only as far as the last complete node. The inner per-node logic is unchanged from today — the fix is entirely in which nodes enter the loop and how the cursor moves.

Note the two distinct exits from the filter gate: a node that passes goes through LLM classification and _apply_edge; a node that fails simply advances the watermark. Both paths advance the cursor — a node yielding no edge is still "fully processed" and must not be re-scanned.

run_auto_linker

Replace the all-rows query SELECT id, content, title, type, space FROM nodes with a windowed, ordered scan:

-- watermark is the composite (updated, id) of the last processed node;
-- shown here as a single column for readability (see "Timestamp ties").
SELECT id, content, title, type, space, updated
FROM nodes
WHERE (updated, id) > (:wm_updated, :wm_id)
ORDER BY updated ASC, id ASC LIMIT :max_nodes_per_run

The inner logic is unchanged: encode → vec_store.search → threshold / cross-space penalty → auto_link_checked / existing-edge skip → _llm_classify_link → _apply_edge. After the loop, write auto_link_watermark = updated of the last fully-processed node to meta (inside a transaction). Per-run cost: O(batch · n) instead of O(n²). The transactional, last-complete-node write is what makes a crash safe.

_find_link_candidates decision (a) — in scope

Extract the candidate scan into a shared incremental generator used by both callers. It reads the same watermark but does not advance it — it is a side-effect-free preview — and replaces ORDER BY RANDOM() with the same deterministic updated ASC window. This removes the duplication the issue calls out and fixes both O(n²) sites with one technique.

Why it stays correct

No link is lost — every pair is discovered when the newer node of the pair is processed.

ConcernWhy it holds
No links lost Every possible pair is discovered when the newer node of the pair is processed. vec_store.search is symmetric and auto_link_checked deduplicates, so the older side need not be re-scanned.
Updates re-enter the delta A node update bumps updated and deletes the node's auto_link_checked rows (memory_engine.py :806 / :850 / :1201 / :1206), so the node naturally re-appears above the watermark.
Partial run, crash, or max_edges hit mid-node The watermark advances only to the last complete node. Reprocessing is idempotent — checked pairs are skipped and no duplicate edges are created. This is why the watermark write trails the loop, not leads it.
Timestamp ties The cursor is the composite (updated, id), so equal updated values are neither skipped nor repeated.

Testing — TDD first

Tests are written before implementation. Each one pins a single correctness or cost property of the cycle above.

#Property under test
1A run processes only updated > watermark, never the full table; respects the batch limit.
2The watermark advances to the last processed node's updated; never past unprocessed nodes.
3Backlog drains across multiple runs; once the delta is empty a run is cheap — no encode, no search.
4An updated node re-enters the delta; an old↔new pair is created when the new node is processed.
5Absent watermark ⇒ epoch; an empty store ⇒ no-op.
6_find_link_candidates returns only candidates in the watermark window, deterministically, without advancing the watermark.
7Existing auto_link_checked tests stay green — no re-check, invalidation on update.
