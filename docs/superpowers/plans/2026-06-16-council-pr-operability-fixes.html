A maintenance pass that quietly returns "completed" while embeddings are missing is worse than one that fails loudly.

Two council-pr HIGH findings shared one failure class — operability masking. C1: run_all_tasks always returned status: "completed" and HTTP 200 even when a task raised. C2: the scheduler-independent backfill fallback gave up silently after 5 attempts, with no degraded signal and no lifecycle control. The /council plan review escalated C2 into two convergent blockers (CH1 daemon lifecycle/singleton, CH2 outage invisible to /admin/health) and surfaced two scope decisions (I1, I2).

Degraded-signal flow ↑

The fix wires a failure signal through every surface an operator watches — the HTTP response, the health endpoint, and the UI — so a silent outage has nowhere left to hide.

Key decisions — I1 & I2 ↑

I1 — HTTP status A degraded run returns HTTP 503 (via JSONResponse), not just a body field. HTTP-only callers (the 02:00 cron, scripts) that check res.ok now detect the failure without parsing the body. The per-task results map is preserved in the body. See Task 1.
I2 — UI scope The UI fix ships in this PR (not a follow-up), so the operator's primary surface stops masking degraded immediately. See Task 3.
No UI test harness The ui/ project has no test runner (no vitest, no test script). Standing one up is out of scope here — verification for Task 3 is tsc && vite build plus an explicit logic review. A vitest harness is a possible follow-up.

Task 1 — C1 / I1 ↑

T1 run_all_tasks returns degraded + HTTP 503 when any task fails

After the task loop, derive has_errors from the results map (same error: prefix the loop writes) and return a 503 with the degraded body; the happy path stays a plain dict (HTTP 200). The UI and any HTTP-only caller now see the failure. Tests assert the response is a JSONResponse with status_code == 503 for the failure case and a dict for the success case.

has_errors = any(v.startswith("error:") for v in results.values())
if has_errors:
    return JSONResponse(
        status_code=503,
        content={"status": "degraded", "results": results},
    )
return {"status": "completed", "results": results}

Task 2 — CH1 / CH2 / C2 ↑

T2 Lifecycle-aware fallback with degraded signal and indefinite retry

This task subsumes the original C2 while True: the new loop is indefinite and lifecycle-aware. A module-level _fallback_degraded flag is the CH2 fix (consumed by /admin/health when no scheduler exists); the stop event + singleton guard are the CH1 fix. The retry sleeps via stop_event.wait(delay) — an interruptible wait that shutdown wakes immediately.

while not stop_event.is_set():
    attempt += 1
    try:
        run_embedding_backfill(engine)
        _fallback_degraded = False   # recovery observable
        return
    except Exception as e:
        _fallback_degraded = True    # outage observable (CH2)
        logger.warning("... attempt %d failed: %s", attempt, e)
        if stop_event.wait(delay):   # interruptible (CH1)
            return
        delay = min(delay * 2, _BACKFILL_FALLBACK_MAX_BACKOFF)
Plan defect caught during TDD — sleep patch vs. interruptible wait

The first draft of the tests patched time.sleep, but the production loop sleeps via stop_event.wait(delay) (a threading.Event method) — so the patch was a no-op and tests blocked on the real 30s backoff. Fix: tests shrink _BACKFILL_FALLBACK_BASE_BACKOFF to 0.001 instead of patching time.sleep. This keeps the production interruptible-shutdown pattern (CH1) intact rather than regressing to a plain time.sleep.

Task 3 — I2 UI ↑

T3 UI consumes the degraded contract

runAllTasks stops using the generic post helper (which throws on any non-ok) and instead tolerates the 503 degraded response, returning its body. handleRunAll branches on result.status: completed → success toast; otherwise → error toast naming the failed tasks; a thrown/network error keeps the existing "Sleep cycle failed" toast. Verified via tsc && vite build (see the no-UI-harness note).

const result = await runAllTasks();
if (result.status === "completed") {
  onToast("Sleep cycle complete", "success");
} else {
  const failed = Object.entries(result.results)
    .filter(([, v]) => v.startsWith("error:"))
    .map(([task]) => task);
  onToast(`Sleep cycle degraded — failed: ${failed.join(", ")}`, "error");
}
