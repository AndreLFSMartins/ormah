Make tuning parameters keyword-only

Mark `min_relevance`, `auto_temporal`, `spread_activation`, and `query_vec` as keyword-only in `recall_search_structured` to prevent silent floor-dropping when positional arguments drift.

When #220 removed the touch_access parameter, `min_relevance` inherited its positional slot. Pre-existing code passing False in the 4th position now silently means min_relevance=0, removing the relevance floor. The change closes this silent-failure trap by marking tuning parameters keyword-only.

The silent-failure trap

At commit a28837bc, the signature was:

def recall_search_structured(self, query: str, limit: int = 10, default_space: str | None = None, touch_access: bool = True, min_relevance: float | None = None, ...)

touch_access held the 4th positional slot. With it gone, min_relevance inherits that slot — and a caller passing False there gets min_relevance=0, which removes the floor and admits lower-relevance results. No exception is raised; the caller receives silently wider results.

Council R1 filed this as medium (Codex, 0.96 confidence) framed as breaking external callers. The evidence changes that framing.

Why this is not a public contract issue

Verified during design:

  • src/ormah/__init__.py is 0 bytes — `MemoryEngine` is not re-exported.
  • `recall_search_structured` appears in no documentation or README. The documented surface covers HTTP routes, not the engine.
  • `touch_access` appears in no public surface: not in adapters (MCP), not in HTTP API, not in CLI.
  • pyproject.toml declares one entry point: ormah = "ormah.cli:main".
  • All 14 in-repo call sites (4 production/eval, 10 tests) pass at most `query` positionally; everything after is keyword.
  • No known external consumer imports `MemoryEngine`.

This is an internal silent-failure trap, not a public-contract problem. The most likely future victim is a caller inside this repo.

Keyword calls are safe

An unknown keyword flows into `**filters` and is forwarded to HybridSearch.search, which declares fixed named parameters and no `**kwargs` — so it raises `TypeError` loudly. On the FTS fallback, the unknown key is ignored (correct behavior: `touch_access` no longer exists). Neither keyword path corrupts a value.

Only the positional path corrupts, silently.

The change: keyword-only with bare `*`

Mark every tuning parameter keyword-only in the signature:

def recall_search_structured(
    self, query: str, limit: int = 10, default_space: str | None = None,
    *, min_relevance: float | None = None,
    auto_temporal: bool = True, spread_activation: bool = True,
    query_vec: Any | None = None, **filters,
) -> list[dict]:

`query`, `limit` and `default_space` remain positional — exactly what the 14 existing call sites use. `min_relevance`, `auto_temporal`, `spread_activation` and `query_vec` become keyword-only.

Contract and guarantees

  • A call with 4 or more positional arguments raises `TypeError` at call time.
  • No existing call site changes; all 14 already comply.
  • `touch_access` is not reintroduced. #220 removed it deliberately.
  • The guarantee outlives this specific parameter: any future reordering of tuning parameters can no longer be absorbed silently by a positional caller.

Test plan

One contract test, added to tests/test_engine/test_confirmed_use_contract.py:

Test: `test_recall_search_structured_rejects_positional_tuning_args`

with pytest.raises(TypeError):
    engine.recall_search_structured("caching architecture", 10, None, False)

Worked example

  • Before the change: the call is accepted, `min_relevance=False` coerces to `0.0`, the floor is dropped, nothing raises. `pytest.raises(TypeError)` fails with DID NOT RAISE — the test is RED for the exact reason it targets.
  • After the change: Python raises `TypeError: recall_search_structured() takes from 2 to 4 positional arguments but 5 were given`. GREEN.

The assertion reaches the defect: deleting the `*` in the future turns it red again.

The positive side — keyword calls still work — needs no new test. The 14 existing call sites exercise it throughout the suite.

Rejected alternatives

Deprecation shim

Reintroduce `touch_access` as an ignored keyword-only parameter emitting `DeprecationWarning`. Rejected: resurrects a name #220 deleted on purpose, adds dead machinery for zero known consumers, and — decisively — leaves the positional trap open, which is the only part that corrupts.

Document only

Note the break in the PR description and change no code. Rejected: cheapest option, but leaves the silent-floor trap live for the next internal caller.

Out of scope

**filters swallows any misspelled filter keyword (e.g., `tierz=` for `tiers=`), silently on the FTS fallback and loudly on the hybrid path. This is pre-existing (not introduced by #220) and wider than this change. Reported upstream as its own issue; not fixed here.
