ADR-0004 Async Ingest Implementation Plan

Nudge + Server Cursor • Beta-first delivery on local-main

Execution order: 1 → 2 → 3 → 4 → 5 → 7 → 6

Overview & Delivery Model

Goal: Implement ADR-0004: the hook becomes a pure nudge (POST /ingest/nudge → 202), the server owns the single ingest cursor (the watcher's .session_watcher_state) and advances it on job completion, the watcher's handler becomes an always-on Ingest worker, and an extraction timeout stops re-burning quota without ever quarantining data a provider outage merely delayed.

Beta-first delivery (council R5, decisive): Two independently verified facts kill the "branch from upstream/main and cherry-pick" recipe: (1) No ingest-provider seam upstream — llm_client.py there exposes only llm_generate and memory_engine calls it directly; (2) The watcher upstream is ~222 lines behind (1203 vs 1425 local) with none of the primitives Tasks 3/7 build on. Every task targets the Beta (local-main) in a worktree.

Global Constraints

  • Never checkout a branch in Tools/ormah — it is the live Beta (whisper hooks break). All work in a git worktree.
  • Sequencing: PR #153 edits cmd_whisper_store, which Task 5 largely deletes. Merged at 66405d9; later upstream sync may conflict there.
  • Out of scope: worker concurrency (issue #150), durable job table, any whisper-inject behavior.
  • ⚠️ Test env caveat: tests/test_setup*.py can touch the real ~/.claude — verify survival by parsing JSON, never grep -i ormah.
  • ⚠️ Throwaway server: MUST set ORMAH_MEMORY_DIR — a wrong key is silently dropped and the process opens the live store.
  • Timeout knob: extraction budget is the existing claude_cli_timeout_seconds (config.py:66, .env-overridable).

Council Amendments (R1–R5)

(a) Error seam
src/ormah/background/llm_errors.py holds LlmTimeoutError and LlmCancelledError; its only raiser is the fork-only claude_cli adapter.
(b) Timeout never quarantines on lateness alone
A timeout counts toward the per-slice cap only when both hold: provider-health evidence (another slice succeeded since this slice's previous timeout) AND the slice has already been shrunk to the floor. A big-but-valid slice gets smaller until it fits instead of being dropped; an outage never consumes the cap.
(c) Cancellation is not a timeout
Shutdown cancel raises LlmCancelledError → EXTRACT_ERR_CALL_FAILED → uncapped TRANSIENT, so restarts can never quarantine a healthy slice. The engine catches it BEFORE any broad handler.
(d) Reconcile scope depends on the enabled flag
Periodic reconcile runs for EVERY install, but its SCOPE depends on the flag. Flag ON → discovers never-seen files within the lookback AND resumes any cursor not at EOF. Flag OFF → recovery-only: processes ONLY transcripts that already have a state entry (a cursor behind EOF, or a boundary_pending nudge the user's own hook sent).
(e) Configured-but-absent watch dirs still yield a handler
Session_watcher_dir points at a path that does not exist yet. Start_session_watcher must still return one SessionWatch (root created, handler live) so a later nudge for a transcript under it is accepted. The hook keeps its legacy cursor until it sees a 202.
(g) A nudge carries session-boundary semantics
The endpoint persists a pending marker BEFORE answering 202 (so a crash is recoverable) and forces a flush past the idle/min-turn gates.

Task 2: EXTRACT_ERR_TIMEOUT — Timeout counts toward the per-slice cap

Implement health-gated timeout classification with shrink-before-quarantine logic. A timeout counts toward MAX_EXTRACT_FAILURES ONLY when provider-health evidence exists (another slice succeeded since this slice's previous timeout). Before quarantine, halve the slice size until reaching the floor.

Files

  • Modify: src/ormah/engine/memory_engine.py (constants ~L54-61; _extract_memories_llm L2842-2886)
  • Modify: src/ormah/background/session_watcher.py:942-954 (classification)
  • Test: tests/test_background/test_session_watcher.py

Semantics

Health gate (council R1): A timeout MAY be evidence about the slice — but provider congestion times out every slice. A timeout counts toward MAX_EXTRACT_FAILURES ONLY with provider-health evidence: some slice extracted successfully since THIS slice's previous timeout (proves the provider was healthy while this slice kept failing). Without that evidence → uncapped TRANSIENT.

Shrink before quarantine (council R4): Health evidence proves the provider works; it does NOT prove the slice is corrupt. A big-but-valid slice can time out while smaller ones succeed. A bracketed timeout first HALVES the slice before counting toward the cap. Deriving the floor with min(MIN_SLICE_BYTES, flush_bytes) matters: a configured flush_bytes=1000 must never be RAISED to a 4000 constant.

Implementation Overview

  • Module-level monotonic success marker _LAST_EXTRACT_OK: float, set at the end of every successful _ingest_session
  • Per-slice state field extract_fail_at (monotonic timestamp), persisted next to extract_fail_offset
  • Atomicity (council R2): decision AND state write happen in ONE locked mutation
  • Add constant EXTRACT_ERR_TIMEOUT in memory_engine.py
  • New helper _mark_slice_timeout() to merge extract_fail_at + optional extract_shrink_level
  • Parse call uses max_bytes = max(floor, flush_bytes >> shrink_level)
  • On success, clear extract_fail_at, extract_shrink_level, and counters

Implementation Steps

  1. Write 6 comprehensive test cases covering outage scenario, cancellation, big-slice shrink, floor quarantine, one-success atomicity, and regression guard
  2. Run tests to verify they fail
  3. Add EXTRACT_ERR_TIMEOUT constant to engine
  4. Wrap ingest_llm_generate call to catch LlmTimeoutError and return EXTRACT_ERR_TIMEOUT
  5. Implement timeout classification in watcher with health gate, shrink levels, and floor detection
  6. Add module-level and per-slice tracking fields
  7. Run tests to verify they pass
  8. Lint and commit

Task 4: POST /ingest/nudge — 202, feeds the worker

Add a fire-and-forget endpoint that enqueues a transcript for immediate ingest with session-boundary semantics. The endpoint persists a durable pending marker and bypasses idle/min-turn gates, but respects the safe-boundary parse and all cap/quarantine rules.

Files

  • Modify: src/ormah/api/routes_ingest.py
  • Modify: src/ormah/background/session_watcher.py (SessionHandler.nudge)
  • Test: tests/test_api/test_routes_ingest.py

Interfaces

Consumes:
app.state.session_watches and SessionWatch/SessionHandler from Task 3
Produces:
SessionHandler.nudge(path: Path) — thread-safe enqueue with boundary semantics, all DURABLE (council R5/R6): merges {"boundary_pending": True} into the transcript's state entry, schedules ingest with zero debounce.
POST /ingest/nudge body {"path": str, "session_id": str|null} → 202 {"status": "accepted"}; 404 file missing; 422 path outside watch dirs.

Semantics

Durability (council R5/R6): The pending marker lives in the state file, so a crash, timeout, or provider failure cannot lose the boundary intent. Every later attempt (retry, reconcile, startup drain) re-derives force_flush from it.

Zero debounce (council R6): A SessionEnd nudge must not wait out the 60s debounce. nudge() schedules immediately while keeping the in-flight guard so a concurrent Observer event still coalesces.

Safe-boundary parsing: _ingest_session reads boundary_pending from the already-loaded entry and treats it as force_flush. It bypasses ONLY the idle-threshold and min_turns gates. The safe-boundary rule (closed content only) and every cap/quarantine rule stay untouched.

Implementation Steps

  1. Write 4 API tests covering acceptance, path validation, 404 on missing file, and durability of pending marker with cursor preservation

  3. Run tests to verify they fail
  4. Implement SessionHandler.nudge() with atomic state merge and immediate scheduling
  5. Add force_flush derivation in _ingest_session
  6. Apply force_flush to idle/min_turns gates and clear flag on success/no-progress
  7. Implement POST /ingest/nudge endpoint with path validation and 202 response
  8. Run tests to verify they pass
  9. Lint and commit

Task 5: Hook becomes a pure nudge — client cursor machinery deleted

Rewrite the hook to post to /ingest/nudge instead of parsing, checking min-turns, or managing cursors. The server owns the cursor and does the extraction. On failure, queue the nudge in an outbox for later retry.

Files

  • Modify: src/ormah/adapters/cli_adapter.py — rewrite cmd_whisper_store
  • Modify: integrations/claude-plugin/hooks/hooks.json — timeout 300 → 30
  • Modify: src/ormah/setup.py — timeout change in configure_claude_hooks
  • Test: tests/test_whisper/test_whisper_out.py, tests/test_setup.py

Nudge Outbox (council R6)

If the POST fails (server down, non-202), the hook appends the transcript path to whisper-nudge-outbox.jsonl in the cache dir and exits 0. Every subsequent hook fire first drains that outbox (best-effort, oldest first, dropping paths whose file no longer exists) before sending its own nudge.

Concurrency (council R7): PreCompact is an async hook and several sessions can fire at once. Use append-only JSONL with fcntl.flock around every open: an append needs no read, and the drain takes an exclusive lock, rewrites survivors to a temp file, and os.replaces it atomically.

Cap by age (council R7): Drop entries older than ~30 days or whose transcript no longer exists. This keeps the hook dumb — no polling, no blocking, no timers — while making the boundary event survive an outage longer than session_watcher_lookback_hours.

Task 7: Bounded shutdown — cancel live claude -p extractions on stop

With the worker always-on and a ~2400s extraction budget, every install could hang a restart for up to ~40 min waiting on one subprocess.run that cannot see the stop event. Keep the drain uncapped, but make the in-flight call FINISH FAST — cancel the live child process.

Files

  • Modify: src/ormah/background/llm/claude_cli_adapter.py (fork-only: subprocess tracking + cancel)
  • Modify: src/ormah/background/llm_client.py (upstream: generic cancel dispatcher)
  • Modify: src/ormah/background/session_watcher.py:1374-1395
  • Test: tests/test_background/test_claude_cli_adapter.py, tests/test_background/test_session_watcher.py

Semantics

Cancellation vs. timeout (council R2): A killed extraction returns a failure, the cursor does NOT advance, and the startup drain re-ingests the slice on next boot. Cancellation raises LlmCancelledError (NEVER LlmTimeoutError): a cancel says nothing about the slice; the engine maps it to EXTRACT_ERR_CALL_FAILED → uncapped TRANSIENT, so restarts can never quarantine a healthy slice.

Instance-scoped state (council R6): The cancel event must be instance-scoped, not module-global. The same process can run a second FastAPI lifespan; a stale cancel event would poison every later call. With instance scoping, a rebuilt adapter starts clean and a surviving one is re-armed by resume().

Shutdown order (council R4): Cancelling only just before the drain would still hang for the full budget. Required order: set stop events → cancel pending timers → cancel active calls → observer stop → join startup thread → drain handlers.

Implementation Steps

  1. Write 7 comprehensive tests covering termination, idle noop, semaphore abort, fast-fail handling, adapter re-arm, and shutdown ordering

  3. Migrate subprocess.run to Popen with tracking in claude_cli_adapter
  4. Implement cancel_active() on adapter with SIGTERM → wait 5s → SIGKILL sequence
  5. Make cancel event and process set instance-scoped
  6. Add event checks before spawn and after semaphore acquire
  7. Implement resume() to clear the cancel event for post-rollback re-use
  8. Implement dispatcher cancel_active_llm_calls() and resume_llm_adapters() in llm_client
  9. Call cancellation in correct shutdown order in session_watcher
